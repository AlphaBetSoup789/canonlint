# M3.5 — Entity resolution fix (LAUNCH BLOCKER)

Written 2026-08-05 after auditing `demo/holmes-continuity-report-live.md` (live run, Aug 4, $28.45).
**Do not publish the live report or launch M4 until this milestone's acceptance test passes.**

## Audit result

319 contradictions. Random sample of 12 drawn from outside the largest cluster: **1 true positive, 11 false positives.** Estimated true precision 5–10% against the M2 gate of ≥90%.

Extraction and adjudication are working. **One layer is broken: `src/ingest/resolve.ts`.** The adjudicator reasons correctly on the inputs it is handed; it is being handed claims bound to the wrong entities.

## Root causes, in priority order

### 1. Resolver over-merges on generic descriptions (causes ~90% of false positives)

Unnamed or generically-described subjects — "a man", "the fellow", "our visitor", "the house" — are being resolved to existing named entities instead of creating a new entity or being dropped. Because match probability rises with table size, this compounds as the corpus grows, which is why M2 passed on a small draft and M3 failed at 60 stories.

Observed failures:

- **Achmet magnet.** 120 of 319 contradictions (38%) cite one excerpt — Achmet's description in *The Sign of the Four* Ch. XII. Every generically-described male in the canon resolved to Achmet.
- **Mary Morstan absorbed Jabez Wilson** (*The Red-Headed League*) — producing claims that she has fiery red hair, is "obese, pompous, and slow", and wears a frock coat and Albert chain. Also absorbed **Mary Holder** (*The Beryl Coronet*) on first-name collision alone.
- **Place collapse.** 221B Baker Street, 3 Lauriston Gardens, Pondicherry Lodge, and Birlstone Manor merged into a single entity.

**Fix:**

- Extraction must emit a `subject_specificity` field: `named` | `definite_description` | `generic`. Only `named` subjects are eligible for cross-work entity resolution. `generic` subjects resolve within the current work only, or are dropped.
- Resolution requires a **name-token match**, not description similarity. Description similarity may only *disambiguate between* candidates that already share a name token; it may never *create* a match on its own.
- Shared given name is not a match. "Mary Morstan" vs "Mary Holder" must not merge. Require full-name match, an explicit in-text apposition ("Mary, my wife"), or an alias the resolver recorded with a citation.
- Add a per-entity claim-count anomaly check to the run summary: any entity accumulating claims from more than ~8 distinct works is flagged for human review before the report is generated. Achmet would have tripped this immediately.

### 2. First-person pronouns bind to the narrator regardless of speaker

Dialogue and embedded narration are attributed to Watson. Turner's "my wife died young" (*Boscombe Valley*) became a claim about Watson's wife, poisoning every later Mrs. Watson claim.

**Fix:** extraction must track the *speaker* of quoted dialogue and bind first-person possessives to that speaker. If the speaker cannot be determined with confidence, drop the claim — do not default to the narrator.

### 3. Figurative language read literally

"Found the cage empty and the bird escaped" (a person fleeing) was matched against a child who died of yellow fever.

**Fix:** add `figurative` to the `modality` enum. Figurative claims are stored but never used as either side of an adjudication.

### 4. Adjudicator doubt does not route away from Contradictions

In at least one entry the adjudicator explicitly reasoned that the description belonged to a different character — and still emitted a contradiction. Its own uncertainty about entity identity is being discarded.

**Fix:** the adjudicator returns an explicit `same_entity_confidence`. Below threshold, the result routes to **Uncertain**, never to Contradictions. This is the constraint-3 precision rule applied at the identity level, and it is the cheap safety net that would have caught all of the above.

### 5. Report quality (cosmetic, but do it in the same pass)

- 138 of 319 entries (43%) are titled just "contradiction". Every entry needs a real one-line summary or it isn't readable.
- **Cluster the output.** Group by (entity, attribute) and report unique contradictions with occurrence counts. "Watson's wound: 1 contradiction, 14 occurrences" is both more honest and more readable than 14 separate entries.
- The live report's header still carries the mock-provider boilerplate claiming "$0 model spend" — false for this file and embarrassing if published. Header must state provider, model, date, and real cost ($28.45).

## Acceptance test

1. Re-run the full 60-story live pipeline.
2. Draw a **random sample of 30** contradictions. Hand-verify each against the source text.
3. **Pass: ≥27/30 correct (90%).** Below that, do not launch — iterate.
4. The Achmet entity must hold claims only from *The Sign of the Four*.
5. No single canon excerpt may account for more than 10% of contradictions.
6. Expect the total to fall from 319 to roughly 15–40 distinct contradictions. **A much smaller number is the success condition, not a regression.** The famous Doyle inconsistencies — the wandering war wound, Watson's Christian name, the Mycroft eye-colour drift — must survive.

## Cost control

Re-running the full corpus costs ~$28 each time. Before spending it:
